Technical Specification: IndexedDB Storage Core & Serverless Ephemeral P2P Sharing Pipeline

Overview & Objective

Implement local persistence using IndexedDB for full replay history, board state, and custom configurations, alongside a 100% serverless, zero-backend sharing pipeline. Players can share exact game seeds, turn diffs, and replay trajectories using 6-character room/shortcodes via open public WebSocket relays (or offline QR codes) without running or maintaining any centralized server.

1. Local Persistence Architecture (IndexedDB)

While localStorage manages simple UI preferences, Undoku uses IndexedDB (undoku_db_v1) to store rich structured game objects, solver metrics, and step-by-step turn histories without storage limits or UI thread blocking.

Schema Definition (db.ts)

export interface SavedGameRecord {
  id: string;                 // UUID or seed hash
  timestamp: number;          // Epoch milliseconds
  difficulty: string;         // 'easy' | 'medium' | 'hard' | 'extreme' | 'impossible'
  boardRows: number;          // Subgrid Br (default 3)
  boardCols: number;          // Subgrid Bc (default 3)
  seed: number;               // PRNG seed integer
  initialGrid: number[][];    // Given starting state
  userGrid: number[][];       // Current or final user state
  solutionGrid: number[][];   // Validated solution matrix
  turnHistory: TurnDiff[];    // Chronological array of user moves
  metrics: Record<string, any>; // 28-metric cognitive analytics object
  isCompleted: boolean;
  durationSeconds: number;
}

export interface TurnDiff {
  step: number;
  r: number;
  c: number;
  val: number;
  prevVal: number;
  timestamp: number;
}


Storage Operations (IndexedDBCore)

saveGame(record: SavedGameRecord): Auto-saves active board state on every valid move.

getReplays(): Returns lightweight list of completed games for history UI.

loadReplay(id: string): Retrieves full TurnDiff[] array for animated playback.

clearHistory(): Complete privacy wipe.

2. Compact Binary Payload Serialization (serializer.ts)

To support instant P2P transmit over open relays or local QR codes, game payloads are compressed into tiny bitfield strings (< 256 bytes for standard solves).

Payload Compression Layout

Header (4 bytes): Protocol Version (4 bits) | Box $B_r$ (4 bits) | Box $B_c$ (4 bits) | Difficulty Enum (4 bits) | Mode Flags (16 bits)

Seed (4 bytes): 32-bit unsigned PRNG seed uint32

Turn Diffs Array: Each turn encoded into a single 16-bit uint16:

Cell Row $r$: 4 bits ($0..15$)

Cell Col $c$: 4 bits ($0..15$)

Placed Value $v$: 4 bits ($0..15$)

Flags / Action Type: 4 bits (e.g. Erase, Hint, User Move)

// Compact Payload Generator
export function serializeGamePayload(game: SavedGameRecord): string {
  const buffer = new ArrayBuffer(8 + game.turnHistory.length * 2);
  const view = new DataView(buffer);
  
  // Header & Seed
  view.setUint32(0, game.seed, false);
  view.setUint16(4, (game.boardRows << 12) | (game.boardCols << 8) | 0x01, false);
  
  // Compact Turn History
  game.turnHistory.forEach((turn, idx) => {
    const packed = (turn.r << 12) | (turn.c << 8) | (turn.val << 4) | (turn.prevVal & 0x0F);
    view.setUint16(8 + idx * 2, packed, false);
  });
  
  // Convert to Base64URL string
  const bytes = new Uint8Array(buffer);
  return btoa(String.fromCharCode(...bytes))
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=+$/, '');
}


3. Serverless P2P / Shortcode Sharing Pipeline

To issue short 6-character room codes (#UDK-9X4A) without hosting a database or backend, Undoku leverages Open Public WebSocket Relays (e.g., Nostr public relays or open MQTT over WSS brokers like EMQX) as an ephemeral pub/sub exchange.

       [ PLAYER A (Host) ]                                [ PLAYER B (Peer) ]
                │                                                  │
                │ 1. Serializes Game Payload (< 250 B)              │
                │ 2. Generates Code: "UDK-9X4A"                    │
                │ 3. Publishes to Topic / Channel:                 │
                │    "undoku/rooms/UDK-9X4A"                       │
                ├───────────────────────┐                          │
                │                       ▼                          │
                │         [ Public WSS Relay Node ]                │
                │         (Zero-backend / Ephemeral)               │
                │                       │                          │
                │                       │ 4. Peer types "UDK-9X4A" │
                │                       │    Subscribes to topic   │
                │                       └─────────────────────────►│
                │                                                  │ 5. Decodes binary payload
                │                                                  │ 6. Loads exact seed & replay into IndexedDB


A. Ephemeral Shortcode Protocol (p2p.ts)

Host Action:

Host clicks "Share Shortcode".

Engine serializes payload and hashes seed + timestamp to produce a 6-character room code (e.g., 8F92A1).

Engine connects to a public WSS relay (wss://broker.emqx.io:8084/mqtt or Nostr wss://relay.damus.io), publishes payload under topic undoku/share/8F92A1 with a 15-minute TTL, and listens for peer acknowledgement.

Peer Action:

Peer clicks "Join Code" and inputs 8F92A1.

Engine fetches topic undoku/share/8F92A1, receives the binary payload, decodes the seed, grid parameters, and replay diffs, and saves the imported puzzle directly into local IndexedDB.

B. Offline Canvas QR Code Generator (Fallback)

For device-to-device transfers with zero internet connection:

Engine renders the compact Base64 payload directly to an on-screen HTML Canvas QR Code.

Second device scans with camera to load the exact game instantly.

4. F-Droid & FossDroid Compliance Verification

Zero Tracking: Data exchanged over public relays contains zero telemetry, zero device identifiers, zero personal information, and zero tracking tokens.

Pure Client Execution: Relays act strictly as dumb message-passers. Payload parsing occurs exclusively within client-side WebAssembly / JS.

100% Offline Integrity: If offline, local IndexedDB storage and local QR code rendering function without network errors or degradation.

Acceptance Criteria

[ ] Active board state and turnHistory auto-persist to IndexedDB (undoku_db_v1) without impacting canvas frame rates.

[ ] User can view, replay step-by-step, or delete saved puzzle records from local history.

[ ] Compressed binary serializer packages seed + settings + 50 turn diffs into under 256 bytes.

[ ] Generating a 6-digit shortcode successfully broadcasts via open WSS relay and reconstitutes the exact puzzle on a second browser.

[ ] Camera scanning of offline canvas QR code opens and loads target puzzle instantly.
